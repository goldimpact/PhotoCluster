# 自动主体归类：实验实现与后续计划

## 当前入口：统一自动发现主体

界面已撤掉主体类别与模型选择，统一发送 `subject_engine=auto`。历史 `general/anime`
API 仅为旧客户端和离线对比保留，不是当前产品操作。旧的语言重载设置不会恢复这些选项。
下文各模型说明是内部实现和历史评测记录，不要求用户挑选引擎。

当前流水线对全部媒体保留 DINOv2 特征比较；本地 MobileNetV3 画面风格分类器按抽样帧
估计补充特征的适用性。3d/bangumi/illustration 分数之和至少 0.8 的帧启用 CCIP 补充
比较。该门槛是工程预设，不是经过独立校准的适用性概率，也不验证画面只有一个角色。
当前判定版本为 `subject-auto-deferred-identity-support-v17`。基础流程：两帧都适用时，以身份特征判断；
两帧都不适用时使用下面的多区域核验。只有一帧适用时证据冲突，暂不合并，不退回画风
相似度。检查全部帧对，拒绝最高分帧对后仍可查找其他符合规则的帧对；最终统一按原始
参考直接匹配，不沿成员链扩张。路由冲突可能造成跨画风正例漏分，这一代价是明确的。

通用候选召回保留原来的廉价最高局部分数（新核验分数的上界），仅对候选加强核验：
四个空间窗口枚举 24 种一一配对，至少三个配对的余弦分数达到当前门槛，且整图余弦
至少 0.45；最终分数为 0.4 × 整图 + 0.6 × 四对区域平均分。全局 patch 平均特征不计为
独立区域。同一个目标区域不能重复支撑多个来源区域，一小块相近不能代表整幅图。
窗口本身仍有重叠，不是分割得到的主体部件，因此多区域支持也不是主体身份的证明。
v3 保持上述匹配门槛，但修复旧动画抽样迁移：增量扫描仅重新提取缺少当前关键帧的
动态媒体，普通照片和已有完整关键帧继续复用。动态媒体的向量、路由、同源特征、
逐对核验和完整分组缓存均隔离抽样版本，避免升级关键帧后仍用旧低清特征。
修复抽样不代表主体身份误判已经解决。

这些修复针对单局部高分、重复利用同一区域、路由冲突回退三个已知误合并入口。
CCIP 的身份分数本身仍可能对不同主体给出高分；相似背景覆盖多个窗口时也可能通过。
合成特征反例和既有四图公开演示只能验证局部行为，不能证明身份准确率。实际错组的
本地复核已暴露当前规则仍会误收不同主体；正确成员与错误成员的分数存在重叠，不能
把调高门槛当作根治。私人回归数据与报告不提交仓库。论文路线、候选复核及验收要求见
[主体身份识别研究](SUBJECT-IDENTITY-RESEARCH.md)。v4 可加载经过导出校验的本地 DreamSim
感知编码器，作为候选复核（见下节）；Qwen 研究模型不参与正式分类。

### v16 可选联合身份复核及支持密度

可选的 CCIP v2 编码器为原补充核验未通过的候选提供第三份身份证据。两侧原帧的画面
域分数均须至少 0.95，同一帧对还须通过感知、语义、小型与大型身份核验，再按需加载
新模型。默认门槛分别为感知 0.50、SigLIP 0.88、小型身份 0.82、大型身份 0.82、新身份
0.83；更宽/更严时遵循相应预设，新身份门槛为 0.81/0.87。这是开发校准组合，不是
三个模型赞成就代表身份确定；原路由不一致时必须有两侧一致的高置信画面域支持。

只有联合身份参考证明的单张补收，才可使用额外的组内支持密度条件。现有局部补收的
至少三个/半数组员要求保留。对最多 64 个不同 SHA 成员的冻结目标组，计算各成员
直接匹配其他原成员的数量，取其 25% 分位数向上取整、至少三个；联合身份补收可在
这个数量与原半数要求中取较低者。成员和参考不变，新加入文件不能反过来提供支持。
不同组同时合格仍拒绝。组内比较计入每媒体 32 次的总核验预算，统计只完整计算一次；
组过大或预算不足则保持原半数要求，不凭部分统计放宽规则。

新增特征保存于独立 `subject-identity-extra.sqlite3`，按模型 SHA、预处理和抽帧身份
隔离；每次最多新增编码 512 个媒体、每批最多四帧，内存保留 64 项。达到预算保守
跳过，没有计算不代表身份不匹配。旧模型特征不清空，完整分类结果随策略版本更新。

```text
python scripts/setup_identity_extra.py
```

安装约 150 MB，OpenRAIL 许可；依赖现有局部及其前置资源，不自动下载。UI 显示
“已启用联合身份复核”，不增加角色/物体选择菜单。首次提取会增加耗时，后续可复用。
扩充公开开发回归未增加已知误配，私人样本有少量收益；仍非独立留出准确率证明。

### v15 排除明确实物画面的角色路线

原风格分类器的 `3d` 类并不等于适用角色身份编码器，真实拍摄的玩具、瓶子、杯子等
也可能被判入。画面域复核资源可用时，对原路由启用身份的帧先检查 `real` 分数；
达到 0.90 则关闭该帧的角色路线，继续进入通用区域核验。没有明确实物证据时保留
原路由，不要求所有角色帧通过更高的新正向门槛，也不新增用户类别选择。

这是一项降低域外误混的保护。公开 COIL-20 四个固定视角的开发检查显示明显减少
误混，但也损失部分正确配对，且仍有跨物体错误；不能宣称已解决一般物体身份识别。
该数据为低分辨率灰度、简单背景，不能代表手机相册。角色开发回归保持原结果。
当前画面域资源随进阶身份复核依赖启用，缺少这些可选资源时保持基础路线。

路由按帧保存原始概率并在本次分类应用策略，不改写旧概率缓存。策略版本变化只要求
重新分类，图像特征兼容，现有分组不自动覆盖。额外域推理仅用于原路由启用的帧所属
媒体，可复用已有域缓存。

### v14 稳定的参考图平局规则

优先级仍为分辨率、清晰度和文件大小；三项相同的媒体再按 SHA-256 和稳定媒体键
确定顺序。MediaStore 或目录枚举顺序不再影响同质量媒体的参考选择、候选预算与
后续分组。同一媒体集合和相同缓存/资源条件下，改变输入排列会得到相同结果。

这是一项确定性修复，不以哈希值推断身份，不使用文件名作为角色线索，也不保证
固定排序是召回最高的排列。策略版本升级后重新分类应用新规则，模型特征兼容，
无需重新提取或清空缓存。冷工作预算和可用缓存仍可能影响候选覆盖范围。

### v13 对早期落单媒体补充复核

局部复核启用时，已有组完成合并后，再检查早期未能归组的单张媒体。只复用本次已
提取的身份特征检索共同参考；候选组须有至少四个不同 SHA-256 的文件，参考图必须
通过局部身份核验，并获得至少三个、且不少于原组一半不同内容文件的直接支持。
相同文件副本不能增加支持数量。满足条件的候选组必须唯一，否则保持未归组。

目标参考保持不变，支持证据来自补收之前的成员快照；新增成员不参与后续判断，不
搬走已有多成员组内的媒体。每项成员仍直接匹配原参考，不沿新成员传播身份。
仅检查最多四个检索候选组，“唯一”指这四个候选范围，不保证全库身份唯一。

候选参考索引按组轮流收集，最多 8192 帧，以 2048 帧块比较；最多复核 4096 个单张，
累计核验请求不超过本次媒体数的 32 倍。预算不足以完成当前媒体的歧义检查时，不
接受该媒体；缺少既有特征时保守跳过，不为此预提取全图库。已有相册范围和取消规则
保持不变。策略升级使分类结果需重新计算，所有兼容模型特征继续复用。

已在私人及扩充的公开开发样本中验证，但样本量仍有限；多成员支持不是准确率或删除
保证。没有局部资源时保留原有归组流程，用户无需额外选择主体类别。

### v12 通用画面路线的身份反证

扩充公开开发样本后发现，原风格路由会将部分漫画交给通用区域路线；区域、感知和
语义相似仍可能混合不同身份。已安装画面域与进阶身份模型时，通用路线的候选帧对
增加冲突核验：两侧画面域分数均至少 0.95，且小型与大型身份分数都低于 0.75，
则不接受这一帧对的通用画面匹配。域判断不确定或任一身份模型没有强烈反对时，
保留原有行为。这些门槛来自开发校准，不是身份不一致的概率。

先检查小型模型，再按需读取大型模型；只处理已成为通用匹配候选的帧对，单次任务
保存最多 8192 项冲突掩码。冲突作用于同一原始帧对，继续搜索其他符合条件的帧；
第一轮候选建议、最终核验与补充通用路线保持一致。身份与局部路线仍须通过自己的
同帧核验，不以一项负分否定整个动画。共同参考及跨组支持规则保持不变。

策略版本升级会要求重新分类，现有模型特征和局部缓存兼容；不自动清缓存或改写
现有分组。没有可选资源时保持基础核验。当前证据仍主要来自角色开发样本，真实
物体的域误判影响尚缺少独立验证，不能宣称通用身份准确率。

### v11 按需局部身份复核

可选的约 12 MB 检测器定位单个人物周围的头发、配饰与上半身上下文，不替换通用
路线。没有检测或检测到多个人物时跳过，不隐式选择主体。动态媒体暂只定位已有抽帧
序列的中间帧；这是一项明确的召回限制，不代表逐帧主体检测。

先复用原有身份向量补查组间候选，包括非参考成员。只索引原路由允许的帧，按组轮流
取样，最多 16384 帧（约 48 MiB），以 64×2048 块计算，每帧最多四个邻组。索引
超出预算时保守跳过，可能漏掉关联；检索不提取新模型特征。

原核验失败后才按需定位：两侧同帧画面域分数均至少 0.90，原图 SigLIP 至少 0.80、
小型身份分数至少 0.75。局部/局部及局部/原图比较还须通过 v10 的小型身份门槛、
v9 的大型身份、感知与语义门槛，所有证据仍对应同一原始帧对。保持共同原图参考和
两条成员不复用的跨组支持；记录参考帧、匹配帧及裁切像素坐标，不沿成员传播身份。

每次任务最多新增分析 512 个候选媒体；已存在的局部缓存可继续读取。无检测结果也
保存，内存最多保留 64 项。达到预算后仍使用原有路线，不承诺本次检查完全部局部
候选。复用完整分类结果时不会暗中继续计算；需要重新计算分类才会再进入该阶段。
冷启动增加开销，后续可复用独立 SQLite 缓存。模型、预处理、抽帧及策略分别版本化，
不清空其他兼容特征。截图边框裁切没有接入，检测器也不是通用物体身份识别器。

较大身份编码器延后到局部的小型身份、语义和感知证据通过后才调用，原图的大型身份
特征也按需读取。局部缓存可以暂时只含前三项特征；后续补齐时复用已记录的帧与裁切
位置，不重新检测，不将“尚未计算”当成否定匹配。每次最多新增 512 项大型局部特征。
旧版完整局部缓存直接兼容；此次调度优化不改变模型、预处理或判定阈值。

```text
python scripts/setup_local_context.py
```

需已安装感知、SigLIP、进阶身份和画面域资源；不自动下载，界面显示“已启用局部身份
复核”。检测器模型卡标注 MIT，身份编码器仍适用各自许可。开发回归改善不能外推为
全图库准确率，跨画风漏分与既有误例仍存在。

### v10 补充画面域核验

原风格模型的 `not_painting` 类别包含游戏截图、聊天记录和宣传图，不能据此推断其中
没有可比较的角色。可选的约 17 MB `deepghs/anime_real_cls` 分类器用于补充候选复核，
不替换第一轮路由，也不把画面域当成身份结论。只有原核验均未通过、同一帧对已满足
v9 的语义与感知门槛，且原路由至少一侧未启用身份时才加载域分数。

两侧域分数均至少 0.90 后，还须小型 CCIP 分数达到更宽/推荐/更严的 0.85/0.87/0.91，
再通过 v9 较大 CCIP 身份核验。所有信号必须对应同一帧对；域判断冲突拒判，不回退到
画风分数。沿用共同原图参考、两条不复用成员的跨组支持及原有工作预算。
开发样本发现单独使用域分类器与较大模型会新增负例匹配，因此保留双身份核验。
多模型一致仍不是正确率保证，尚不能宣称通用主体或任意跨画风识别已解决。

```text
python scripts/setup_domain_refine.py
```

资源按需安装，不自动下载；依赖感知、SigLIP 及进阶身份模型。独立缓存保存原始域
概率（不做向量归一化），按模型 SHA、预处理与抽帧版本隔离。首次仅处理候选；
已有兼容特征继续复用。界面显示“已启用跨画面身份复核”，添加或移除资源后旧结果
标记为需重新分类。许可为 OpenRAIL，参见第三方声明。

### v9 按需进阶身份复核

可选 CCIP CAFormer B36 为小型身份编码器未通过的候选提供不同容量的身份特征。
它仍是面向单角色图像的专用模型，不能声称识别任意真实人物或物体。只在已安装
感知与 SigLIP 补充模型、两帧均适用身份路线、同帧对已有语义与感知支持且原复核
未通过时提取。每次最多四帧，独立有界缓存，不为整个媒体库预先重提取。

更宽/推荐/更严预设分别要求：较大模型相似分数至少 0.80 / 0.82 / 0.87，SigLIP 至少
0.88 / 0.88 / 0.93，感知至少 0.50 / 0.50 / 0.60。大模型上游推荐距离尺度与原小模型
不同，不能直接交换特征或阈值；这些是多信号开发预设，非独立准确率保证。

补充阶段的整组合并除共同参考逐项核验外，新增两条来源成员和目标成员均不复用的
跨组直接匹配，防止单个泛化过宽的参考图连接两个身份。部分重分配仍要求每个核心
成员有另一组至少两个成员支持。开发之外的上游公开测试子集发现过单参考误合风险，
因此不能省略这项组级校验；公开子集可能与模型训练重叠，不称为独立模型留出集。

可选安装约 384 MB，模型为 OpenRAIL 许可，与项目 MIT 许可不同：

```text
python scripts/setup_identity_refine.py
# 如需代理，可追加 --proxy http://127.0.0.1:7897
```

只在资源存在时启用，界面显示“已启用进阶身份复核”。首次候选提取会增加时间，后续
可复用；没有资源时继续现有路线，不自动下载。特征、模型和策略分别版本化，升级仅
使相应分类结果失效，不清空兼容媒体特征。路由冲突或未被候选检索发现的跨画风案例
仍可能漏分。这不是用大模型取代整条流水线，也不使用双图生成模型作最终裁判。

### v7–v8 可选主体补充复核

检测到 `subject-complementary.onnx` 且已安装感知复核模型时，在 v6 归组完成后追加一次
候选检索与复核。SigLIP 2 提供不同来源的视觉语义特征，不是身份模型；单独得分再高也
不能合组。每个至少两成员的组抽取最多四个分布样本，每个样本保留最多四个候选邻组，
检索门槛 0.88。特征按需提取，最多四帧一批，内存缓存 64 个媒体，检索按 2048 帧分块；
增量结果保存在独立 SQLite 缓存。检索索引上限 16384 帧（约 48 MiB），先轮流为各组
取样，再增加额外样本；超出预算的部分保守跳过，可能漏合。首次启用会增加处理时间，后续可复用。

复核保留路由冲突拒判，所有信号必须来自同一对抽样帧：

| 预设 | 身份路线：CCIP / SigLIP / 感知 | 通用路线：SigLIP / 感知 / 区域门槛 |
| --- | --- | --- |
| 更宽 0.65 | 0.82 / 0.90 / 0.45 | 0.90 / 0.45 / 0.52 |
| 推荐 0.72 | 0.82 / 0.92 / 0.50 | 0.93 / 0.50 / 0.55 |
| 更严 0.80 | 0.85 / 0.95 / 0.60 | 0.96 / 0.60 / 0.65 |

v8 给身份路线增加“强感知支持语义”的备选条件：CCIP 门槛仍如表，SigLIP / 感知
分别为更宽 0.88 / 0.60、推荐 0.88 / 0.60、更严 0.93 / 0.70。与表中条件任选其一，
但身份、语义、感知及路由仍必须在同一帧对满足；不能跨帧拼接强证据。该条件只用于
第二轮补充复核，不修改第一轮分类。预设经过开发样本对照，仍需独立留出集验证。

通用路线仍需三个不同区域的一对一支持及整图最低支持；区域门槛是结合另外两项信号的
开发预设，不是用单局部最高分代替身份。第一轮和原有复核不变，补充阶段也必须遵循
共同参考及部分重分配的多成员支持约束。模型分数不是身份概率，开发样本改善不能
外推为全媒体库准确率。仍存在跨画风漏分及相似主体误混。

可选安装（约 95 MB，Apache-2.0，校验固定 revision 和 SHA-256）：

```text
python scripts/setup_complementary.py
# 如需本地代理：
python scripts/setup_complementary.py --proxy http://127.0.0.1:7897
```

不自动下载，不上传照片，不新增主体类别/模型选择菜单；界面会显示是否启用。
新版结果签名包含模型身份，旧结果会提示重新分类；无需清空其他特征。只有完整任务成功
才发布新结果。移除或添加可选模型同样会使相关主体结果失效。

### v6 身份与外观证据配合、支持核心重新分组

v5 要求两个组整体通过同一参考，少量外观差异较大的成员会阻止其余成员归在一起。
v6 保留整组合并，同时允许提取两个组中有充分证据的共同核心：所有成员仍直接匹配
新参考，且每个成员至少直接匹配另一来源组的两个不同成员，反复移除不满足支持的成员。
只有核心规模优于原最大组（同规模时比较组大小平方和）才接受；余下成员分别保留，
重新核验其参考，单个剩余成员回到未归组媒体。一个桥接成员不能单独促成这种重分配。
来源组不足两个成员时不进入该流程。

仅在组间复核时，增强身份路线新增一组互补门槛，保持同帧对及双侧路由一致性。
第一轮仍保留原有门槛，避免扩展证据改变初始参考选择、制造新的孤立成员：

| 相似程度 | 较强身份分数至少 | 同帧对感知分数至少 |
| --- | --- | --- |
| 更宽（0.65） | 0.85 | 0.45 |
| 推荐（0.72） | 0.87 | 0.50 |
| 更严（0.80） | 0.91 | 0.60 |

原有身份与感知门槛仍可独立通过；新路线仅用更强身份证据补充外观变化，不给通用区域
路线降低门槛，也不让路由冲突回退到画风。预设来自开发样本，不是独立留出集准确率，
仍可能误分或漏分。裁剪特征的开发实验增加过误收，因此没有接入正式流程。
本次仍未解决不适用身份路线的表情图及部分跨画风角色，不声称通用身份识别已完成。

候选关系最多八个邻组、每对最多十六个参考、剩余组最多四个参考候选；包含交叉支持
及剩余组核验的总预算为媒体数的六十四倍，逐对缓存上限 8192。预算耗尽保留已确认
结果及其余原分组。取消不发布部分结果。新策略使完整分组缓存失效，基础特征仍可复用。

### v5 共同参考图复核（v6 的基础）

首次分组仍按画质顺序选择参考图。结束后利用该轮已有的候选关系，对至少各有两个成员的组
尝试重新选择共同参考图，减少同一主体因初始参考图外观不同而拆成多个组的情况。
新参考必须是组内某个原始媒体；合并后的所有成员（含旧参考、之前合入的成员）必须直接
通过相同的逐帧核验，任何一个失败都不接受该参考。不会降低门槛，也不沿相似链直接合并。
更新参考后重新生成成员的分数及对应帧信息；主体组仍不提供可删除的重复体积建议。

此步骤仅改善可被现有核验规则支持的拆组，不是新的身份模型，也不能保证不误合。
为控制大媒体库开销，每个媒体最多保留四个基础候选，每条组间关系最多四个候选成员，
每组最多八个候选邻组，每次合并最多尝试十六个参考；总核验请求预算为媒体数的十六倍，
另有已合并结果的成员证据重建。使用有界的逐对缓存，不构建全库两两矩阵。
预算不足或未找到合格参考时保留分组，单独显示复核进度并支持取消。候选裁剪意味着仍会漏合。

策略版本变化会使旧分类结果失效；下一次“同步并分类”重新分组即可，现有兼容的特征及模型
缓存继续使用，不必清空缓存或强制重新提取所有媒体。只有整个任务成功才发布新结果。

### v4 可选感知复核

检测到 `data/models/subject-perceptual.onnx` 时，统一入口自动启用 DreamSim DINOv2-B/14
单分支复核。先使用原有候选检索和基础核验，再仅为进入核验的媒体计算感知特征；
同一个帧对必须同时满足原有规则与感知门槛，不能拼接动画中不同帧的有利分数。
角色路径不以 DINO 或颜色相等为前提，但也需要感知复核。初始实验预设如下：

| 严格程度 | 感知余弦最低值 | 角色模型最低分（启用复核时） |
| --- | --- | --- |
| 更宽 | 0.50 | 上游默认约 0.8215 |
| 均衡 | 0.60 | 0.85 |
| 更严 | 0.70 | 0.88 |

这些门槛依据开发回归设置，非独立校准的身份概率；跨画风、换装或明显重绘可能漏分。
更宽档可以提高召回，也会增加误合并。尚未声称全图库高准确率。缺少导出模型时保留
基础流程与原有门槛，界面明确显示“基础核验”或“已启用感知复核”，不让用户选模型。

运行时使用 ONNX Runtime，标准安装保留 CPU 路径；若其提供 CUDA provider 则优先使用。
不逐对生成文字。特征按媒体 SHA、抽样版本及模型哈希写入 `subject-perceptual.sqlite3`，
内存最多保留 64 项，推理每批最多 4 帧，取消时保存已经完成的特征。
增加、更换或移除模型会使完整匹配签名变化；兼容的其他特征继续复用。

普通安装按钮仍只准备基础约 191 MB 资源。可选编码器约 330 MiB，当前需要一次本地导出，
不是默认安装自动提供的能力。使用隔离环境安装导出依赖 `torch`、匹配的 `torchvision`、
`dreamsim==0.2.1`、`peft==0.17.1`、`onnx`、`onnxruntime`。从 DreamSim 官方
`v0.2.1-checkpoints/dreamsim_dinov2_vitb14_checkpoint.zip` 解压权重，准备 DINOv2 官方
源码 revision `7764ea0f912e53c92e82eb78a2a1631e92725fc8`，再运行：

```text
python scripts/export_subject_perceptual.py --weights <local-weights> --dino-source <local-checkout> --output data/models/subject-perceptual.onnx
```

导出器检查三个输入权重/配置的固定 SHA，离线执行并使用合成输入验证上游/ONNX 数值一致。
正常运行无需 PyTorch。模型、导出元数据和私人回归报告不提交 Git。

资源共约 191 MB，一次准备，已下载的模型复用；新增约 17 MB 的路由模型使用 MIT 许可。
`scripts/setup_subject_auto.py` 固定版本与哈希校验。静图特征缓存保持兼容，新增
`subject-routing.sqlite3`；完整结果签名包含组合策略版本、全部模型哈希和特征版本，
不会复用原来的单引擎分组。增量扫描即可，无须删除兼容缩略图、关键帧或特征。

统一流水线在下述四图上游演示上只生成 1/2 一组。开发期间该小样例参与了组合规则调整，
因此它不是留出验证集。合成测试另覆盖自动混合通用与补充匹配、无跨帧泄漏、冲突处理、
相册范围、取消和非链式约束。尚未证明通用主体身份准确率，也没有实现人物重识别、
多主体检测或对幻想生物的专项验证。入口统一不能消除模型覆盖面的局限。

## 动漫角色引擎（CCIP）

此前界面曾提供独立引擎选择，现已撤销；下面说明内部补充模型的能力边界。
角色引擎使用专门按角色相似性训练的 CCIP，而不是手工加一个颜色/轮廓分数。训练得到的
身份表征旨在允许姿态、构图、画风变化；不使用颜色必须相同或 DINO 整图相似的硬门槛。
这并不保证任意换色、遮挡或重绘仍可识别。当前没有检测/分割多个角色，也未增加可靠的
通用物体身份识别。动物吉祥物、多人画面、极端恶搞仍可能很差。

输入遵循上游 RGB、双线性缩放至 384 方形和 CLIP 归一化；每帧编码为 768 维单位向量。
上游距离为 `(1 - cosine) / 2`，均衡距离门槛为 `0.17847511429108218`；界面内部以
`1 - distance` 作为相似分数，非身份概率。更宽/更严使用距离 0.22 / 0.15，仅为可调预设。
检索使用有界矩阵块，每成员直接匹配原参考，保持非链式分组；跨媒体取最佳抽样帧对。
不重新命名角色，不修改手机目录。推理当前使用 CPU，首次提取比 DINOv2 更昂贵。

模型约 150 MB，固定版本、SHA-256 验证，许可为上游 OpenRAIL。可在界面安装，或运行
`python scripts/setup_character.py --proxy http://127.0.0.1:7897`。独立缓存为
`thumbnails/characters.sqlite3`，使用模型哈希、特征版本、媒体哈希；分组签名区分引擎。
换引擎后可增量分类，兼容缩略图/关键帧保留，不会拿旧 DINO 特征冒充角色特征。

### 已有证据与边界

本地运行上游公开示例 1、2、6、7（imgutils revision
`46df848dc4d20ac93f4919a40e2636d5f7c19766` 的 `docs/source/api_doc/metrics/ccip/`）。
按上游示例标注，1/2 为同角色，其余五对不同。DINOv2 均衡档漏掉 1/2；CCIP 距离 0.1658
通过均衡门槛，其余五对距离 0.3923–0.4372 均拒绝。矩阵距离实现与上游 metric ONNX
在这四项上的最大差异约 `1.8e-7`。这只是上游演示，**不是独立、留出的角色准确率评测**。
示例图片和模型均不提交仓库，不能把六对结果外推为用户图库准确率。

`scripts/evaluate_identity.py` 可对本地标注的正反例对离线比较两引擎并输出 TP/FN/FP/TN，
不会下载、上传、访问手机或改动分类缓存。应加入同角色跨画风、变色、同色不同角色、
相似脸型不同角色等反例再决定改进方向，而不是不断放宽阈值。

## 通用外观引擎（DINOv2，保持兼容）

已实现独立 `subject` 模式，无需先选样例。使用本地 DINOv2 Small INT8 编码器自动提出
角色或物体分组；它不是专门训练的角色身份识别器，不自动命名角色，跨画风二创准确率
尚未在独立标注集上验证。下面原有的多样例交互方案保留为后续方向，不是当前操作步骤。

当前实现保留全画面，以 224 × 224 letterbox 输入；一次推理取得全局描述子、全图 patch
均值和四个重叠区域均值。区域是固定窗口，不是检测出的主体。帧对分数为 0.4 × 全局余弦
+ 0.6 × 最佳区域余弦，且全局余弦至少 0.45；媒体对取最佳帧对。均衡 / 更宽 / 更严门槛
为 0.72 / 0.65 / 0.80，均为未校准的实验预设，不是身份概率。

图片、GIF 与视频复用已有预览及抽样帧，动态媒体最多均匀取八帧。检索使用有界矩阵块，
再校验直接参考匹配，没有新增 SIFT、扭曲或逐对大模型调用。当前模型推理与主体检索
使用 CPU。主体组不计算候选删重体积，也不沿已加入成员继续链式扩展。

特征保存于当前实例 `thumbnails/subjects.sqlite3`，按媒体 SHA-256、模型文件 SHA-256
和特征版本校验；结果签名同样包含模型身份。可通过界面安装约 24 MB 公共模型，或使用
`python scripts/setup_subject.py --proxy http://127.0.0.1:7897`。权重固定版本且校验哈希，
照片不上传，分类不调用外网接口。

缓存面板有三档清理：分组、分析缓存、完整媒体库缓存。预览范围后确认执行，扫描或同步
期间拒绝清理；模型、设置、操作日志、未知文件、其他实例与手机原文件保留。必要状态文件
和数据库空表仍可能占少量空间，显示大小不代表能精确释放的字节数。

测试覆盖真实 ONNX 推理、维度与归一化，以及合成向量的局部匹配、背景门槛、相册范围、
取消、直接参考约束、模型和结果缓存失效。这不等于已验证真实二创图的识别率。

## 目标和现有缺口

同一角色可以跨表情、姿态、服装、画风、二创、恶搞和媒体格式出现；同一物体也会
跨角度、光照与背景出现。这是身份关系，区别于共享原画面的变体关系，也区别于
“都是猫 / 都是汽车”的类别关系。一个画面还可能含多个主体，应允许多标签展示。

当前 CLIP ViT-B/32 整图特征经过中心裁剪，比较画面整体；主体在边缘、背景占比大、
画风变化等因素均可能影响结果。单参考图、固定相似阈值的自动分组不能保证上述身份
关系。更低阈值、更长的相似链或换一个更大模型都不能直接视为能力已经达成。

## 建议的首个可验证版本

1. 独立入口“按主体整理”，区分“同一个主体”和“同一类事物”，不作为删重建议。
2. 用户从现有手机媒体选择几张不同外观的样例，给主题命名；必要时指定主体区域。
   这里只保存现有媒体的引用和局部区域，不向虚拟文件夹导入或添加手机文件。
3. 使用本地多样例检索提出候选。整图和主体区域分别编码，先廉价召回，再对候选验证；
   不对全库每一对都调用昂贵模型。图片与 GIF / 视频关键帧使用统一入口。
4. 用户确认或排除候选，将反馈保存为本地主题样例。每个候选必须直接匹配明确的已确认
   样例，不让自动接受的候选继续充当新样例，防止链式漂移。显示命中的样例和待确认状态。
5. 后续再研究无需样例的自动主题发现。主题命名和自动发现不应成为第一版检索的前提。

多样例只能改善对用户意图的表达，不能保证模型理解任意二创身份。模型与主体定位器
需要先评测：通用视觉特征、图文特征、动漫领域模型各有适用范围，目前不指定未经验证的
赢家。文字描述可以作为辅助；不能依赖 OCR 字幕或生成的角色名作为身份事实。

## 发布前评测

在有授权、保留于本地的独立标注集上，与当前 CLIP 基线比较。覆盖同角色跨画风、
同画风不同角色、换装、局部遮挡、多角色同框、普通物体，以及静图与动画视频之间的匹配。
评测集须与建主题时的样例分离，不能用同一原图的压缩副本冒充跨画风正例。

分别报告候选召回率、确认前精确率、不同主体的误合并、每主题检索延迟、首次建库成本和
峰值内存 / 显存。身份和类别任务分别评价，不承诺通用“像人一样”的识别率。
性能开销较大的验证按需启用，保留 CPU 回退、取消与进度反馈。

## 数据与兼容性

推理始终在本地；可选模型需固定版本、校验下载并确认再分发许可。主题、样例、负例、
区域特征与反馈属于私有缓存，不提交仓库。新索引按模型、预处理、帧抽样和主题修订号
分开版本化，不覆盖已有近重复、变体和 CLIP 缓存。

主题文件夹仅为虚拟视图，不能隐式变成手机目录。删除与移动仍走现有预览和内容校验流程；
同一媒体的所有主题引用都要同步更新。新能力上线前需补充 API、缓存、操作同步及中英文
界面测试，不能仅新增一个模式名称或降低阈值。
