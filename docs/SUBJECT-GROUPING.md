# 自动主体归类：实验实现与后续计划

## 当前入口：统一自动发现主体

界面已撤掉主体类别与模型选择，统一发送 `subject_engine=auto`。历史 `general/anime`
API 仅为旧客户端和离线对比保留，不是当前产品操作。旧的语言重载设置不会恢复这些选项。
下文各模型说明是内部实现和历史评测记录，不要求用户挑选引擎。

当前流水线对全部媒体保留 DINOv2 特征比较；本地 MobileNetV3 画面风格分类器按抽样帧
估计补充特征的适用性。3d/bangumi/illustration 分数之和至少 0.8 的帧启用 CCIP 补充
比较。该门槛是工程预设，不是经过独立校准的适用性概率，也不验证画面只有一个角色。
当前判定版本为 `subject-auto-perceptual-candidates-v4`。基础流程：两帧都适用时，以身份特征判断；
两帧都不适用时使用下面的多区域核验。只有一帧适用时证据冲突，暂不合并，不退回画风
相似度。检查全部帧对，拒绝最高分帧对后仍可查找其他符合规则的帧对；最终统一按原始
参考直接匹配，不沿成员链扩张。路由冲突可能造成跨画风正例漏分，这一代价是明确的。

通用候选召回保留原来的廉价最高局部分数（新核验分数的上界），仅对候选加强核验：
四个空间窗口枚举 24 种一一配对，至少三个配对的余弦分数达到当前门槛，且整图余弦
至少 0.45；最终分数为 0.4 × 整图 + 0.6 × 四对区域平均分。全局 patch 平均特征不计为
独立区域。同一个目标区域不能重复支撑多个来源区域，一小块相近不能代表整幅图。
窗口本身仍有重叠，不是分割得到的主体部件，因此多区域支持也不是主体身份的证明。
v3 保持上述匹配门槛，但修复旧动画抽样迁移：增量扫描仅重新提取缺少当前关键帧的
动态媒体，普通照片和已有完整关键帧继续复用。动态媒体的向量、路由、同源特征、
逐对核验和完整分组缓存均隔离抽样版本，避免升级关键帧后仍用旧低清特征。
修复抽样不代表主体身份误判已经解决。

这些修复针对单局部高分、重复利用同一区域、路由冲突回退三个已知误合并入口。
CCIP 的身份分数本身仍可能对不同主体给出高分；相似背景覆盖多个窗口时也可能通过。
合成特征反例和既有四图公开演示只能验证局部行为，不能证明身份准确率。实际错组的
本地复核已暴露当前规则仍会误收不同主体；正确成员与错误成员的分数存在重叠，不能
把调高门槛当作根治。私人回归数据与报告不提交仓库。论文路线、候选复核及验收要求见
[主体身份识别研究](SUBJECT-IDENTITY-RESEARCH.md)。v4 可加载经过导出校验的本地 DreamSim
感知编码器，作为候选复核（见下节）；Qwen 研究模型不参与正式分类。

### v4 可选感知复核

检测到 `data/models/subject-perceptual.onnx` 时，统一入口自动启用 DreamSim DINOv2-B/14
单分支复核。先使用原有候选检索和基础核验，再仅为进入核验的媒体计算感知特征；
同一个帧对必须同时满足原有规则与感知门槛，不能拼接动画中不同帧的有利分数。
角色路径不以 DINO 或颜色相等为前提，但也需要感知复核。初始实验预设如下：

| 严格程度 | 感知余弦最低值 | 角色模型最低分（启用复核时） |
| --- | --- | --- |
| 更宽 | 0.50 | 上游默认约 0.8215 |
| 均衡 | 0.60 | 0.85 |
| 更严 | 0.70 | 0.88 |

这些门槛依据开发回归设置，非独立校准的身份概率；跨画风、换装或明显重绘可能漏分。
更宽档可以提高召回，也会增加误合并。尚未声称全图库高准确率。缺少导出模型时保留
基础流程与原有门槛，界面明确显示“基础核验”或“已启用感知复核”，不让用户选模型。

运行时使用 ONNX Runtime，标准安装保留 CPU 路径；若其提供 CUDA provider 则优先使用。
不逐对生成文字。特征按媒体 SHA、抽样版本及模型哈希写入 `subject-perceptual.sqlite3`，
内存最多保留 64 项，推理每批最多 4 帧，取消时保存已经完成的特征。
增加、更换或移除模型会使完整匹配签名变化；兼容的其他特征继续复用。

普通安装按钮仍只准备基础约 191 MB 资源。可选编码器约 330 MiB，当前需要一次本地导出，
不是默认安装自动提供的能力。使用隔离环境安装导出依赖 `torch`、匹配的 `torchvision`、
`dreamsim==0.2.1`、`peft==0.17.1`、`onnx`、`onnxruntime`。从 DreamSim 官方
`v0.2.1-checkpoints/dreamsim_dinov2_vitb14_checkpoint.zip` 解压权重，准备 DINOv2 官方
源码 revision `7764ea0f912e53c92e82eb78a2a1631e92725fc8`，再运行：

```text
python scripts/export_subject_perceptual.py --weights <local-weights> --dino-source <local-checkout> --output data/models/subject-perceptual.onnx
```

导出器检查三个输入权重/配置的固定 SHA，离线执行并使用合成输入验证上游/ONNX 数值一致。
正常运行无需 PyTorch。模型、导出元数据和私人回归报告不提交 Git。

资源共约 191 MB，一次准备，已下载的模型复用；新增约 17 MB 的路由模型使用 MIT 许可。
`scripts/setup_subject_auto.py` 固定版本与哈希校验。静图特征缓存保持兼容，新增
`subject-routing.sqlite3`；完整结果签名包含组合策略版本、全部模型哈希和特征版本，
不会复用原来的单引擎分组。增量扫描即可，无须删除兼容缩略图、关键帧或特征。

统一流水线在下述四图上游演示上只生成 1/2 一组。开发期间该小样例参与了组合规则调整，
因此它不是留出验证集。合成测试另覆盖自动混合通用与补充匹配、无跨帧泄漏、冲突处理、
相册范围、取消和非链式约束。尚未证明通用主体身份准确率，也没有实现人物重识别、
多主体检测或对幻想生物的专项验证。入口统一不能消除模型覆盖面的局限。

## 动漫角色引擎（CCIP）

此前界面曾提供独立引擎选择，现已撤销；下面说明内部补充模型的能力边界。
角色引擎使用专门按角色相似性训练的 CCIP，而不是手工加一个颜色/轮廓分数。训练得到的
身份表征旨在允许姿态、构图、画风变化；不使用颜色必须相同或 DINO 整图相似的硬门槛。
这并不保证任意换色、遮挡或重绘仍可识别。当前没有检测/分割多个角色，也未增加可靠的
通用物体身份识别。动物吉祥物、多人画面、极端恶搞仍可能很差。

输入遵循上游 RGB、双线性缩放至 384 方形和 CLIP 归一化；每帧编码为 768 维单位向量。
上游距离为 `(1 - cosine) / 2`，均衡距离门槛为 `0.17847511429108218`；界面内部以
`1 - distance` 作为相似分数，非身份概率。更宽/更严使用距离 0.22 / 0.15，仅为可调预设。
检索使用有界矩阵块，每成员直接匹配原参考，保持非链式分组；跨媒体取最佳抽样帧对。
不重新命名角色，不修改手机目录。推理当前使用 CPU，首次提取比 DINOv2 更昂贵。

模型约 150 MB，固定版本、SHA-256 验证，许可为上游 OpenRAIL。可在界面安装，或运行
`python scripts/setup_character.py --proxy http://127.0.0.1:7897`。独立缓存为
`thumbnails/characters.sqlite3`，使用模型哈希、特征版本、媒体哈希；分组签名区分引擎。
换引擎后可增量分类，兼容缩略图/关键帧保留，不会拿旧 DINO 特征冒充角色特征。

### 已有证据与边界

本地运行上游公开示例 1、2、6、7（imgutils revision
`46df848dc4d20ac93f4919a40e2636d5f7c19766` 的 `docs/source/api_doc/metrics/ccip/`）。
按上游示例标注，1/2 为同角色，其余五对不同。DINOv2 均衡档漏掉 1/2；CCIP 距离 0.1658
通过均衡门槛，其余五对距离 0.3923–0.4372 均拒绝。矩阵距离实现与上游 metric ONNX
在这四项上的最大差异约 `1.8e-7`。这只是上游演示，**不是独立、留出的角色准确率评测**。
示例图片和模型均不提交仓库，不能把六对结果外推为用户图库准确率。

`scripts/evaluate_identity.py` 可对本地标注的正反例对离线比较两引擎并输出 TP/FN/FP/TN，
不会下载、上传、访问手机或改动分类缓存。应加入同角色跨画风、变色、同色不同角色、
相似脸型不同角色等反例再决定改进方向，而不是不断放宽阈值。

## 通用外观引擎（DINOv2，保持兼容）

已实现独立 `subject` 模式，无需先选样例。使用本地 DINOv2 Small INT8 编码器自动提出
角色或物体分组；它不是专门训练的角色身份识别器，不自动命名角色，跨画风二创准确率
尚未在独立标注集上验证。下面原有的多样例交互方案保留为后续方向，不是当前操作步骤。

当前实现保留全画面，以 224 × 224 letterbox 输入；一次推理取得全局描述子、全图 patch
均值和四个重叠区域均值。区域是固定窗口，不是检测出的主体。帧对分数为 0.4 × 全局余弦
+ 0.6 × 最佳区域余弦，且全局余弦至少 0.45；媒体对取最佳帧对。均衡 / 更宽 / 更严门槛
为 0.72 / 0.65 / 0.80，均为未校准的实验预设，不是身份概率。

图片、GIF 与视频复用已有预览及抽样帧，动态媒体最多均匀取八帧。检索使用有界矩阵块，
再校验直接参考匹配，没有新增 SIFT、扭曲或逐对大模型调用。当前模型推理与主体检索
使用 CPU。主体组不计算候选删重体积，也不沿已加入成员继续链式扩展。

特征保存于当前实例 `thumbnails/subjects.sqlite3`，按媒体 SHA-256、模型文件 SHA-256
和特征版本校验；结果签名同样包含模型身份。可通过界面安装约 24 MB 公共模型，或使用
`python scripts/setup_subject.py --proxy http://127.0.0.1:7897`。权重固定版本且校验哈希，
照片不上传，分类不调用外网接口。

缓存面板有三档清理：分组、分析缓存、完整媒体库缓存。预览范围后确认执行，扫描或同步
期间拒绝清理；模型、设置、操作日志、未知文件、其他实例与手机原文件保留。必要状态文件
和数据库空表仍可能占少量空间，显示大小不代表能精确释放的字节数。

测试覆盖真实 ONNX 推理、维度与归一化，以及合成向量的局部匹配、背景门槛、相册范围、
取消、直接参考约束、模型和结果缓存失效。这不等于已验证真实二创图的识别率。

## 目标和现有缺口

同一角色可以跨表情、姿态、服装、画风、二创、恶搞和媒体格式出现；同一物体也会
跨角度、光照与背景出现。这是身份关系，区别于共享原画面的变体关系，也区别于
“都是猫 / 都是汽车”的类别关系。一个画面还可能含多个主体，应允许多标签展示。

当前 CLIP ViT-B/32 整图特征经过中心裁剪，比较画面整体；主体在边缘、背景占比大、
画风变化等因素均可能影响结果。单参考图、固定相似阈值的自动分组不能保证上述身份
关系。更低阈值、更长的相似链或换一个更大模型都不能直接视为能力已经达成。

## 建议的首个可验证版本

1. 独立入口“按主体整理”，区分“同一个主体”和“同一类事物”，不作为删重建议。
2. 用户从现有手机媒体选择几张不同外观的样例，给主题命名；必要时指定主体区域。
   这里只保存现有媒体的引用和局部区域，不向虚拟文件夹导入或添加手机文件。
3. 使用本地多样例检索提出候选。整图和主体区域分别编码，先廉价召回，再对候选验证；
   不对全库每一对都调用昂贵模型。图片与 GIF / 视频关键帧使用统一入口。
4. 用户确认或排除候选，将反馈保存为本地主题样例。每个候选必须直接匹配明确的已确认
   样例，不让自动接受的候选继续充当新样例，防止链式漂移。显示命中的样例和待确认状态。
5. 后续再研究无需样例的自动主题发现。主题命名和自动发现不应成为第一版检索的前提。

多样例只能改善对用户意图的表达，不能保证模型理解任意二创身份。模型与主体定位器
需要先评测：通用视觉特征、图文特征、动漫领域模型各有适用范围，目前不指定未经验证的
赢家。文字描述可以作为辅助；不能依赖 OCR 字幕或生成的角色名作为身份事实。

## 发布前评测

在有授权、保留于本地的独立标注集上，与当前 CLIP 基线比较。覆盖同角色跨画风、
同画风不同角色、换装、局部遮挡、多角色同框、普通物体，以及静图与动画视频之间的匹配。
评测集须与建主题时的样例分离，不能用同一原图的压缩副本冒充跨画风正例。

分别报告候选召回率、确认前精确率、不同主体的误合并、每主题检索延迟、首次建库成本和
峰值内存 / 显存。身份和类别任务分别评价，不承诺通用“像人一样”的识别率。
性能开销较大的验证按需启用，保留 CPU 回退、取消与进度反馈。

## 数据与兼容性

推理始终在本地；可选模型需固定版本、校验下载并确认再分发许可。主题、样例、负例、
区域特征与反馈属于私有缓存，不提交仓库。新索引按模型、预处理、帧抽样和主题修订号
分开版本化，不覆盖已有近重复、变体和 CLIP 缓存。

主题文件夹仅为虚拟视图，不能隐式变成手机目录。删除与移动仍走现有预览和内容校验流程；
同一媒体的所有主题引用都要同步更新。新能力上线前需补充 API、缓存、操作同步及中英文
界面测试，不能仅新增一个模式名称或降低阈值。
