# 主体身份识别：研究路线与验收

本文记录研究方向。DreamSim 已以可选候选复核接入 v4（见当前主体流水线文档）；
其他研究模型没有直接接入。正式流水线以 `photocluster/subject_auto.py` 的版本为准。
实验必须离线运行，不能覆盖用户分组。

v7–v8 另将可选 SigLIP 2 编码器用于第二轮组间候选检索与多信号复核。它的上游任务是
语义理解与检索，不是主体身份识别；单独提高语义分数会混合同类别的不同人物。
开发实验要求通用路线保留多区域支持，身份路线同时满足 CCIP 与感知信号；帧对必须
一致，路由冲突继续拒判。阶段顺序也影响结果，补充复核放在原归组之后以保留既有行为。

不同时间的人工回归集可能包含同一个媒体，且抽帧缓存可能已升级。评测前须按稳定媒体
身份去重，冻结原始抽样帧，为所有模型保持一致的帧索引；不能将历史数组按文件键覆盖
新数组，或将未标注身份的旧负例一律当作新角色的负例。私人测量留在忽略目录，不写入
公开准确率宣传；只有明确标注的身份差异或负配对才能计为误混。

`scripts/evaluate_subject_groups.py` 可对离线保存的完整分组评测正配对保留数、每个身份的
最大组与碎片数、明确跨身份配对和旧负例误合数。输入必须按媒体 ID 去重；未标注的邻居
单独统计，不凭模型猜测标成负例。未出现在分组的媒体按单个碎片计入，避免忽略漏分。
该工具不加载模型、不访问手机、不改写分类结果。

后续开发对照中，固定区域裁剪和轻量前景分割有时改善局部召回，但也可能增加跨身份
匹配；没有作为默认策略接入。双图生成模型在较容易的开发子集上可能表现很好，扩充
困难负例后仍出现假阳性；交换两图顺序的一致投票没有消除共同误判。只报告一个容易
子集或多个模型的赞成票数是不充分的。按语义分数选择动态帧能改善少量漏判，也会把
原本通过的正例改为拒判，必须记录被选帧和完整配对变化，不能把选帧视为无损加速。

## 任务定义

路由实验发现，风格模型 `not_painting` 的上游定义含游戏截图、聊天记录及宣传图，
不是身份模型不适用的直接证据。直接替换全流程路由会改变首轮分组并损失已有正例；
v10 因而只在补充阶段按需核验画面域，且要求两个身份编码器与同帧感知/语义证据。
仅以域分数配合较大身份模型曾新增已知负例匹配，不能省略小型身份核验。
扩大参考搜索预算、重复执行归并、仅凭目标参考和少数成员支持转移照片、另换一版
身份编码器均未在完整分组中获得可靠净收益，没有作为正式默认策略接入。
这些结论来自开发回归；公开角色子集也参与过策略设计，不能再称为独立留出验证。

目标是自动发现同一具体角色、个体或具有辨识度的物体设计，允许姿态、表情、
视角和绘制方式变化。共享类别、画风、背景或配色不足以证明身份相同。
不要求用户先选择动漫、动物或真实物体，也不依赖认识角色名称。

现有 DINOv2 重叠窗口是视觉相似特征，CCIP 是特定领域的角色特征。
二者都可能给不同主体高分。多个窗口相似不等于多个独立主体部件相同；
分数重叠时提高阈值会同时损失正确变体。单元测试通过不能证明识别准确率。

## 可借鉴的论文与公开实现

| 方法 | 用途 | 边界 |
| --- | --- | --- |
| [DreamSim (2023)](https://arxiv.org/abs/2306.09344)、[实现](https://github.com/ssundaram21/dreamsim) | 用人类相似判断微调视觉表征，适合快速候选检索与细节相似度比较 | 感知相似不是身份；姿态、布局和颜色也影响分数 |
| [When Does Perceptual Alignment Benefit Vision Representations? (2024)](https://arxiv.org/abs/2410.10817) | 提供 DINOv2 等单分支和稠密特征版本，并评测实例检索 | 论文检索指标不能外推为任意二创角色准确率 |
| [Deep ViT Features as Dense Visual Descriptors](https://arxiv.org/abs/2112.05814)、[实现](https://github.com/ShirAmir/dino-vit-features) | 共分割与局部对应，减少固定窗口平均带来的信息损失 | 不同个体也可能有相同部件；对应本身不能作身份结论 |
| [A Tale of Two Features (2023)](https://arxiv.org/abs/2305.15347)、[实现](https://github.com/Junyi42/sd-dino) | 融合扩散模型与 DINO 特征改善语义部位对应 | 计算成本较高；语义对应任务允许不同实例 |
| [SAM 2](https://github.com/facebookresearch/sam2) | 图像和视频主体区域分割，可减少背景污染 | 分割器不能判定身份；自动掩码选择也会出错 |
| [Qwen3-VL-Embedding / Reranker (2026)](https://arxiv.org/abs/2601.04720)、[实现](https://github.com/QwenLM/Qwen3-VL-Embedding) | 先向量召回，再同时输入两张图按任务说明复核；公开 2B/8B 权重 | 是相关性模型，尚非通用身份裁判；速度、域外误判和分数校准必须实测 |
| [Qwen3-VL](https://arxiv.org/abs/2511.21631)、[实现](https://github.com/QwenLM/Qwen3-VL) | 本地双图视觉判断，按明确身份要求对比可见特征并允许拒判 | 可能编造特征或混淆身份；生成说明更慢，不能只相信文字解释 |
| [Supervised Contrastive Learning](https://arxiv.org/abs/2004.11362)、[Proxy Anchor Loss](https://arxiv.org/abs/2003.13911) | 用身份标注正例和困难负例训练距离，使同主体跨变体靠近、同风格不同主体分离 | 必须有有权使用的身份数据与独立留出集；不能拿少数反馈训练后再当测试集 |

以上论文都不保证“任意主体、任意二创，一键完美归类”。可行工程方向是组合
候选检索和身份复核，并明确拒判条件，不继续把风格分数直接当身份概率。

## 拟验证的流水线

统一的是用户入口，内部不限制模型数量，也不要求所有输入走同一条计算路径。
候选召回可组合不同特征；身份复核应基于能区分具体主体的证据，不能把不同模型的
未校准分数直接平均。模型错误可能相关，多数同意或全体同意都不等于身份确定。
检测到背景、多人、低清或证据冲突时，可按需补充主体区域、清晰帧或不同验证器；
路由策略本身也要在留出数据上验证，不能凭画风硬划类别或为个别已知组写特例。

1. 图片、动图和视频使用同一媒体入口，保留来源帧索引。检查低分辨率抽样是否丢失
   身份细节；不把动画中的一张过渡空白帧当作主体。
2. 先用可缓存的视觉特征快速找候选。主体定位与前景特征可补充召回，不能只靠某个
   特定类别检测器，否则幻想生物和未见过的物体会被漏掉。
3. 仅对候选与原始组参考执行双图复核。任务说明要求同一具体身份，允许外观变体；
   不把用户指出的文件名、角色名或正负标签写进推理提示。
4. 证据不足时不自动合并。每个成员直接匹配原参考，不借已加入成员传播身份。
   若帧对证据冲突，记录不确定性；单个高分不得悄悄代表整个动画。
5. 若零样本模型仍失败，使用合法标注数据训练身份度量或复核器。用户纠错可作为
   本地明确约束，不能悄悄变成全局训练数据或上传。

## 性能与缓存约束

- 不进行全库逐对大模型推理。候选预算必须实测召回率，不能用固定 top-k 截断后
  声称识别完全不受影响。
- 记录模型加载、单图编码、候选检索、逐对复核分别的耗时与峰值内存/显存。
  GPU 可用时使用有界批次；CPU 路径必须可取消并说明实际速度。
- 复核缓存隔离媒体 SHA、模型 SHA、预处理、帧抽样、任务说明和策略版本，正负结果
  均须失效。改变最终判定时同时检查 Service 结果签名、`semantic.VERSION` 和
  `rules.pair_version` 的职责，不能误用其他模式的旧匹配结果。
- 安装公开模型可以联网，分析媒体时只读取本地文件；禁用遥测与远程代码加载。
  新模型是可选依赖，不应让基础安装自动下载数 GB 资源。

已修复历史抽样兼容性：旧动画特征只有 64×64 `animation_samples`，
`semantic.frame_images()` 在缺少 `frame_path` 时会回退使用它们。新提取器已经生成
更大关键帧，但原 catalog 快速路径只检查 jpg/npz 是否存在，无法自动升级这种旧记录。
现在增量扫描按需升级对应媒体，连同依赖该抽样的向量和最终结果一起失效；
仍保留兼容静图缓存。升级在用户下一次扫描时发生，不会后台修改现有分组。

## 研究结论与状态

增加 [COIL-20](https://www.cs.columbia.edu/CAVE/software/softlib/coil-20.php) 实物多视角
检查后发现，原画风路由经常把实物送入角色路线并产生跨物体误混。固定使用每物体
0°、90°、180°、270° 视角后再计算模型特征，不按结果挑选图片。v15 对画面域模型明确
认定为实物的帧关闭角色路线，减少误混，但牺牲了部分召回且仍有错误。正向要求两个
分类器都高置信同意则会拆散既有正确角色组，没有采用。数据背景简单、灰度且低清，
仅是域外开发回归；模型训练重叠未知，不作手机全库准确率宣传。源图与报告不分发。

顺序敏感性也需要回归：主体流水线按质量选择参考，但同质量媒体原来沿用输入顺序。
对冻结的公开开发特征随机排列时，召回发生变化；v14 增加内容哈希与媒体键平局规则，
使同集合的参考、分组和证据不再随目录枚举顺序改变。这里验证的是可重复性，不能
把某次固定排列的较高配对数宣传成普遍准确率提升。实验阈值和模型保持不变。

对明显黑边截图，分别试验了只清理边框、清理后重新定位局部，以及在补充阶段使用
同一内容区域的全部模型特征。部分配对分数改善没有转化为完整分组收益，直接替换
整图还可能拆散已有组，因此这些预处理暂未接入默认流程。评测须同时检查候选召回、
原参考支持和最终组，不能以某个模型的单对高分代替整条流程的改善。

局部水平镜像实验也使用同一变换后的像素计算全部模型证据，保留原帧索引与整图支持。
虽然新增了一些同身份局部匹配，但未改善当前开发集的最终分组，还增加未标注匹配
机会，暂不增加到正式流程。单对召回改善不足以抵消额外编码开销；新增未标注配对
也不能当作正确或错误的已知事实。

对剩余失败案例，局部 ±30°/±60° 旋转诊断未使共同参考通过全部证据，因此没有扩大
到默认整库计算。另一版身份编码器与既有两个身份编码器联合时，能补充少量正确
配对，但完整分组仍受原参考和成员支持约束，未产生已验证的分组收益。不要仅为
接纳某个失败案例降低支持比例，也不要把多模型赞成直接当作身份概率。这些实验
仍是离线研究，不增加用户依赖或安装大小。

后续组合实验把第三种身份特征与组内支持密度一起比较：固定参考仍须直接通过全部
同帧证据，已有局部补收规则不变，只对新增身份证据研究独立条件。组内配对密度可
解释跨画风组为何达不到固定比例，但不能自行证明新增图片正确。直接替换原支持
条件曾造成另一主体漏收，已拒绝。附加路径在扩充到整个公开角色档案后的完整分组
及新增配对检查中未增加已知误配，私人开发样本出现小幅收益。v16 以可选方式接入，
限制组内统计规模与核验请求，保持冻结成员及原参考约束，并检查冷/热缓存与模型
许可。公开档案仍是开发集，不能视为独立留出准确率证明。

局部复核改善匹配后，一些早期落单媒体已经能通过现有共同参考，仍因旧合并阶段只
处理多成员组而遗漏。直接按参考和少量邻居补收会扩大未标注邻居，不能据此推断
正确。v13 使用局部参考证明、固定原成员支持及不同 SHA 去重，仅补收唯一符合
条件的检索目标。公开开发集从每身份两张扩到四张、五张后，才出现可检验补收的
大组与落单候选；原两张子集不能证明这项策略有效。扩充集已参与开发，非独立留出集。

扩大公开开发样本后，发现原通用区域路线会接受一对身份模型同时反对的不同角色。
v12 将这种反证作为按帧掩码应用于通用核验：保留其他有效帧，统一第一轮候选建议
与补充复核，避免“建议仍按旧规则，最后才否决”改变合并顺序。原有正例与负例、
完整分组均重新回放；并非只验证新发现的那一对。公开样本已用于开发，不能当作
独立留出集。画面域分类也可能错，后续仍需真实物体与跨域负例验证。

开发回归表明，稠密 DINO 对应、人类感知特征、2B 重排与 4B 双图生成判断均有
局限。DreamSim 在部分平面角色变体上分离明显，但另一些主体仍与困难负例重叠。
2B 复核仍存在误合并和漏分；4B 生成判断对提示敏感，严格要求会拒绝正确变体，
强调跨画风容忍后又会接受不同主体。这些单模型没有达到直接替换身份核验的条件；
v4 采用可选感知复核与更保守的角色预设组合，以减少误合并为目标，接受残留错误与
召回损失，不能宣称通用身份已解决。
私有样本的具体数字与模型输出只保存于 `data/`，不作为公开准确率宣传。

后续局部定位实验区分了两个问题：固定窗口可能没有对齐主体，而每组少量检索样本
可能漏掉已有的有效证据。只替换整图为去黑边截图没有稳定的完整分组收益；按检测框
提取头发、配饰及上半身的上下文，在开发样本中改善了部分远景与近景匹配。检测到多个
候选主体时跳过，局部证据仍需原帧的画面域与整图支持，并与同帧身份/感知/语义核验
结合。检测器的脸部框不代表通用主体，也不能让共用脸型成为身份结论。

局部特征之间及局部与整图之间的比较须分别评测：后者可能提高召回，也扩大了匹配
机会。检索可先复用已提取的成员身份特征，再对候选按需定位，无需先为整个库计算
昂贵局部特征。分组参考与跨组支持规则不因此放宽。v11 将通过开发回归的局部上下文
方案作为可选路径接入，使用独立缓存、检索预算和取消检查并保存证据坐标；详见
[当前实现](SUBJECT-GROUPING.md)。这仍是开发校准方案，不是独立准确率保证。

后续并行研究方向包括互补模型与自适应证据复核，以及身份度量学习：收集合法来源的
多外观同身份正例、同画风不同身份困难负例，以主体划分开发/留出集，比较组合策略、
微调表征和双图复核器。生成模型只可提供候选
解释，不得当作可靠标注教师。自动流程仍需不确定性与局部定位，避免类别相似冒充
身份相同；目前没有发布新的身份识别模型。

## 发布前验收

新增身份编码器之后重新检查了“去截图边框后再联合核验”的方案：所有身份、语义和
感知证据均来自同一裁切帧，并保留原始帧与裁切坐标。开发回放中，部分单对匹配有所
改善，但完整分组没有新增收益；遍历相关原始媒体作为共同参考后仍有未通过的成员。
因此不将该裁切方案接入自动分类，也不通过传递相似关系强行合并。单对收益和整组收益
需要分别衡量；后续应补充不同截图布局与相似角色的独立样本，而不是围绕单个漏分调低门槛。

已知错组仅作为开发回归集，私人图像、路径、特征和报告一律留在忽略的 `data/`。
对同一参考分别报告正确成员保留数、错误成员误收数、拒判数，不能只汇报总体正确率。
被当前模型拒绝的配对也应评测，防止漏分被隐藏。

独立留出集应包含同主体跨风格/表情/服装/视角、同风格不同主体、同颜色不同主体、
普通物体、真实动物、幻想生物、多人画面及跨媒体匹配。按主体和来源划分训练与测试，
而不是随机拆分同一图片的压缩副本。冻结提示和阈值后再评测留出集。

仅在候选召回、身份复核、完整分组、取消、缓存失效及 Windows/Linux 工作流都经过
验证后接入正式入口；保持统一自动主体工作流，避免新增让用户选择模型的菜单。

## 离线复现实验

`scripts/evaluate_subject_verifier.py` 是研究工具，不被服务导入。它只使用已下载的
本地 Qwen3-VL Instruct safetensors 权重，不自动安装模型、不访问手机、不修改分组。
依赖在独立环境安装：PyTorch、匹配版本的 torchvision、Transformers 4.57.x、
Pillow、safetensors。GPU 采用 BF16（不支持时 FP16）/SDPA，CPU 采用 FP32；速度必须分别实测。
模型下载和许可证审查应在运行之前完成，不能让研究依赖进入基础 requirements。
本地实验使用的 Qwen3-VL-4B-Instruct / Qwen3-VL-Reranker-2B 官方模型卡标注
Apache-2.0，DreamSim 仓库使用 MIT、DINOv2 使用 Apache-2.0。研究工具不分发权重
或复制上游模型实现；产品集成时仍应为具体选定的资源固定 revision、SHA 与许可证。

输入示例（真实文件与标注留在 `data/`）：

```json
{
  "items": [{"id": "a", "path": "frames/a.png"}, {"id": "b", "path": "frames/b.png"}],
  "pairs": [{"a": "a", "b": "b", "same": true}]
}
```

```text
python scripts/evaluate_subject_verifier.py data/research/manifest.json --model data/research/model --output data/research/report.json --device cuda
```

每项输入是一张明确的图片或抽样帧，脚本不声称完成视频全帧验证。正负标注仅用于
统计，不进入模型提示；默认拒判计为“不合并”，同时单独列出正例/负例拒判数。
输出记录固定任务说明、权重与配置哈希、依赖版本、分辨率预算、耗时、峰值显存及
逐对结果。中断报告标记 `complete=false`，不把部分评测当作完成。

可选 `--verdict-only` 在模型生成完整的第一个 JSON `verdict` 字段后停止，省去后续
文字说明；提示与判定词保持不变。报告明确记录此选项，不能把不完整前缀或自由文本
当成已完成的判断。启用前应对同一输入比对完整输出，确认判定一致；减少生成时间
不会提高识别准确率。这个选项仅在离线研究工具内，不意味着大模型已接入自动分类。

程序在模型加载和媒体分析期间禁用 Hugging Face 联网/遥测，并阻止 Python TCP
连接；只加载本地内置模型实现，不启用 `trust_remote_code`。这不是操作系统沙箱，
运行环境中的依赖仍必须可信。模型文字说明仅供诊断，不能作为身份事实或删除依据。

## 组合策略对照

`scripts/evaluate_subject_ensemble.py` 读取已保存的本地判断，不运行模型，不联网，
不修改分组。对完全相同的有向帧对比较各模型、任一接受、多数接受和全体接受，
分别统计正确/错误接受、正确/错误拒绝及正负例拒判，并列出共同误收的配对。
这些是诊断基线，不是产品合并策略；脚本不拟合权重或选择阈值。

输入含 `cohort`（`development` 或 `held_out`）以及 `reports` 字典；字典键注明
模型及策略版本，各项包含 `complete: true` 和 `pairs`（`a/b/same/verdict`）。
缺失帧对、反向帧对、标签冲突、重复配对或未完成报告会报错，不悄悄取较容易的交集。
使用连续分数的模型需在外部以事先声明的门槛生成判断，并将门槛记入报告标识。

```text
python scripts/evaluate_subject_ensemble.py data/research/ensemble.json --output data/research/ensemble-report.json
```

拒判不能当作反对票，也不能缩小多数票分母。开发集上存在全体误收时，应该补充新的
身份区分证据，并测量错误是否减少；不能通过重复调用同一模型制造更多赞成票。
