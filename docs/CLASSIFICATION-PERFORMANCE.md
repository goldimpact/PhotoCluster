# 分类性能与缓存

“本地处理”不代表无需计算。同源画面模式先准备 SIFT 描述子、旋转感知哈希及检索签名，
随后只对检索出的候选进行几何验证。动态媒体最多比较三个抽样帧，并保留镜像特征。
首次使用该模式、媒体内容变化、抽帧策略升级或明确要求强制重扫时，相关特征需要计算。

特征阶段显示已复用和已计算的文件数。轻量的 `thumbnails/variant-index.sqlite3` 索引
保存检索字段；SHA、提取版本、抽帧身份以及归档大小、修改时间、变更时间都一致时，
无需重新打开每个 NPZ 读取小字段。旧归档首次遇到新索引时验证后自动登记，不必清缓存。
缺失、变化或不兼容的归档继续走原提取流程，损坏归档可从本地预览重建。

准备任务使用持续补充的有界线程队列，按实际完成数量更新进度，再恢复输入顺序供匹配。
不会为了等待一张较慢的动画而暂停整个固定批次。NPZ 使用较低级别的无损压缩，数组内容
不变，但文件可能略大；写入临时文件成功后才替换归档。停止时取消尚未启动的任务，等待
已经开始的提取完成并保存缓存。

几何验证先查询已有逐对判定；全部命中时不解压描述子，也不执行 GPU/CPU 匹配。
仅缺失的比较继续采用现有规则及 CPU/CUDA 路径。以上改动不改变抽帧数量、SIFT 参数、
候选检索范围或匹配门槛，所以不升级识别语义版本，也不使兼容特征或逐对缓存失效。

提取速度仍受 SIFT 计算、动态帧数量、磁盘和 CPU 影响。更多线程或 GPU 不一定更快，
不能将某个缓存阶段的加速倍数视为全程加速倍数。性能检查应分别记录首次计算、缓存复用、
几何验证耗时，并验证优化前后的特征数组及分组结果。用户媒体测量报告仅保留本地，
公开测试使用临时合成媒体。索引归入界面的分析缓存清理范围；无须手动删除它。

自动主体模式的局部复核分两步提取：先计算小型身份、语义和感知特征，三项证据在同一
帧对满足条件后，才读取或提取较大身份模型。原图的大型身份特征同样延后。无合适检测
的结果会缓存，已记录的局部区域无需重新检测。部分特征缓存表示尚未完成全部编码，
不等于该照片不匹配；后来出现合适候选时可补齐。旧版完整局部特征直接兼容。

这项调度优化不改变模型、裁切、采样和相似门槛；需验证冷、热缓存及旧完整缓存的分组
和证据坐标一致，并记录实际编码调用数量。并行负载会影响墙钟时间，不能把一次局部
阶段计时当作整库速度保证。候选提取与检索仍有工作预算，详见主体归类文档。

联合身份补收落单媒体时，先检查候选与固定参考、独立成员的直接支持。达到原有半数组员
要求便可结束；连最低三个独立支持都没有时也无需计算组内密度。只有处在两者之间的
候选，才计算冻结目标组的支持密度。统计仍限制在最多 64 个独立成员，并计入同一工作
预算；目标歧义检查、直接参考规则和相似门槛不变。

合成的 64 成员充分支持场景只需 32 次候选核验，跳过原先预先执行的 4,032 次组内核验。
这不是整库加速倍数：本地开发样本回放没有显示明显时间收益。需要密度的候选仍会执行
组内核验，可能多检查少量候选配对。v17 更新结果策略版本，因为预算消耗顺序改变；
模型、抽帧和特征缓存继续复用，几何逐对缓存与语义模型版本不受影响。
